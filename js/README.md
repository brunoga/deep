# @brunoga/deep-patch

The JavaScript half of [`deep`](https://github.com/brunoga/deep): produce and
apply the same patches a Go server does, so the two can exchange *changes*
rather than whole documents.

```bash
npm install @brunoga/deep-patch
```

```ts
import { diff, applyPatch, reverse, merge } from '@brunoga/deep-patch';

const patch = diff(before, after);          // send this over the wire
const result = applyPatch(replica, patch);  // fold it into a replica
applyPatch(replica, reverse(patch));        // and undo it
```

No dependencies. Ships as TypeScript source, which Node runs directly and any
bundler compiles.

## What it is for

A Go service using `deep` already sends patches to its Go clients — per-tick
game state, an incident's changed fields, a technician's offline edits. This
package lets a browser be one of those clients:

```ts
socket.onmessage = (e) => {
  const patch = JSON.parse(e.data);
  applyPatch(world, patch, { keys: { '/players': 'id' } });
  render(world);
};
```

## Collaborative text

The CRDT half is here too: the same document, awareness and websocket
protocol `deep/ws` serves, so a browser can be a peer of a Go client rather
than a viewer of a server's copy.

```ts
import { connect } from '@brunoga/deep-patch';

const room = await connect({ url: 'ws://host/ws?room=notes', node: 'ana' });
room.onUpdate(() => (textarea.value = room.text));
room.insert(0, 'typing here reaches everyone');
room.announce({ name: 'Ana' });   // presence, and the heartbeat
```

Two people typing at once converge without either asking permission, and a
peer that goes quiet stops being drawn rather than lingering as a ghost.

Positions are counted in **code points**: an astral character is one
character, as it is in Go, so an editor that counted UTF-16 units would place
every later edit one position off.

## API

| Function | Does |
| :--- | :--- |
| `diff(a, b, opts?)` | The operations turning `a` into `b`. |
| `applyPatch(target, patch, opts?)` | Applies a patch, reporting what applied, what was skipped and what failed. |
| `reverse(patch)` | The patch that undoes this one. |
| `merge(base, other, resolver?)` | Combines two patches made against the same starting state. |
| `evaluate(value, condition)` | Evaluates a condition on its own. |
| `equal(a, b)` / `clone(v)` | Structural equality and deep copy. |

`applyPatch` **mutates** `target` where it can, so applying a stream of
patches to a replica does not copy the document each time. Pass a copy —
`applyPatch(structuredClone(v), p)` — when the original must not move. It
returns the patched value too, since replacing the root cannot be done in
place.

### Skips are not failures

An operation whose `if` / `unless` condition does not hold is *skipped*, and
the result counts it separately from a failure. That distinction is the whole
point of conditional writes: "somebody else got there first" is an outcome to
show a user, not an error to retry.

```ts
const result = applyPatch(doc, claimPatch);
if (result.skipped > 0) toast('Someone claimed that already');
```

### Keyed arrays

Go models mark an array's identity field with a `deep:"key"` struct tag, and
diffs then address elements as `/tasks/t3/done` rather than by index — so
reordering is not a change and two writers editing different elements never
collide. That tag is invisible in JSON, so tell this package about it:

```ts
const keys = { '/tasks': 'id' };
diff(before, after, { keys });        // emits /tasks/<id>/... paths
applyPatch(doc, patch, { keys });     // resolves them
```

Without a schema, an array that differs is replaced whole — which is also
what Go's reflection engine does for an untagged slice.

### Guards and allowlists

```ts
applyPatch(doc, patch, { allowedPaths: ['/players/me', '/gems'] });
```

A patch naming anything outside the allowlist is refused entirely, before any
of it runs — the same blast-radius limit a Go server puts on patches it did
not write.

## Compatibility

`test/conformance.test.ts` and `test/crdt.test.ts` run corpora generated by
the Go implementation (`testdata/conformance/`): each case carries a document, a patch, and
the exact result Go produced, including the counts of applied, skipped and
failed operations, and whether the patch reverses cleanly.

The CRDT corpus goes further, because a CRDT cannot be judged one case at a
time: it records real exchanges between replicas — the exact bytes, the text
each ended up with, and each one's state vector — and this implementation
replays them with its clocks pinned where Go pinned them. Matching text is
not enough there; the replicas must agree **down to the encoded bytes**,
which is what shows the edits are identical rather than merely compatible.
`ws/interop_test.go` then puts the two implementations on one websocket and
watches them converge.

Regenerate both with `go test ./internal/conformance/...`.

Divergence between two implementations of a sync protocol is silent — the
replicas simply disagree, with no error anywhere — so the corpus is a merge
gate in CI rather than a nicety.

One rule for Go models that sync with JavaScript, learned from that corpus and
documented in [docs/wire-patch.md](../docs/wire-patch.md): **do not use
`omitempty`** on fields patches address. It makes a zero value and an absent
field identical on the wire, so the two replicas end up holding the same value
and disagreeing about the document.

Paths name fields as the JSON does regardless of whether a type has generated
code — the reflection engine, generated code and the type-safe selectors all
agree since v6.6.0, escaping where RFC 6901 requires it.

One shape still needs care: an anonymously embedded Go struct is addressed by
its type name (`/embMeta/level`) while `encoding/json` promotes its fields to
the outer object, so that path resolves against nothing here. Give such a
field an explicit name and tag.
